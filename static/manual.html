Atlas AdminSysOP

Die universelle Operations-Management-Plattform für Leitstellen, Logistik, Sicherheit und Flottenmanagement. Professionell, sicher, skalierbar.

Version 1.0.0
Ersteller Felix Greis | Atlas GmbH
Backend FastAPI + SQLite
Sprachen DE · EN · FR

Atlas AdminSysOP ist eine webbasierte Echtzeit-Leitstellensoftware. Sie läuft vollständig im Browser ohne Installation – auf Desktop, Tablet und Smartphone. Die Plattform kombiniert Lageführung, Alarmmanagement, Kommunikation, Flottenüberwachung und KI-gestützte Analytik in einer einzigen Oberfläche.

Installation & Start

Einmalige Einrichtung über das Setup-Skript

Das gesamte System wird über eine einzige Datei – setup.sh – eingerichtet und gestartet. Python 3 ist die einzige Voraussetzung.

Voraussetzungen

  • Python 3.9 oder höher
  • pip (Python Paketmanager)
  • Internetzugang für CDN-Ressourcen (Leaflet, Chart.js)
  • Moderner Browser (Chrome 90+, Firefox 90+, Safari 16+, Edge 90+)

Erster Start

Setup-Skript ausführen

chmod +x setup.sh && ./setup.sh

Erstkonfiguration ausfüllen

Beim ersten Start erscheint ein interaktiver Wizard:

  === Atlas AdminSysOP – Erstkonfiguration ===
Organisationsname:    Meine Leitstelle
Einrichtungstyp:      security
Admin-Name:           Max Mustermann
Admin-Benutzername:   admin
Admin-Passwort:       ••••••••
Tailscale aktivieren? [j/N]: N

Server startet automatisch

Nach dem Wizard läuft der Server auf Port 8080.

  ═══════════════════════════════════════════════════════
    Atlas AdminSysOP v1.0.0
    © Felix Greis | Atlas GmbH 2026
    Erreichbar unter: http://0.0.0.0:8080
  ═══════════════════════════════════════════════════════

Browser öffnen

Navigieren Sie zu http://localhost:8080 und melden Sie sich mit den konfigurierten Zugangsdaten an.

Tailscale-Integration (optional)

Atlas AdminSysOP kann über Tailscale aus dem gesamten privaten Netzwerk (auch mobil, auch aus der Ferne) erreichbar gemacht werden. Der Server bindet an 0.0.0.0:8080 und ist dann über die Tailscale-IP direkt zugänglich – ohne VPN-Konfiguration.

Alarmsystem

Automatische und manuelle Alarme mit Push-Benachrichtigung

Alarme können manuell erstellt oder vom System automatisch ausgelöst werden (z.B. bei Sensor-Schwellenwert-Überschreitung oder Flotten-Fälligkeit). Kritische Alarme lösen sofortige Push-Benachrichtigungen auf allen registrierten Geräten aus.

Alarm-Eskalation

Das System prüft alle 60 Sekunden unquittierte Alarme. Alarme, die länger als 10 Minuten unbeantwortet bleiben, werden automatisch auf den nächsthöheren Schweregrad eskaliert.

Quittierung

  • Einzeln quittieren: Klick auf „✓ Quittieren" beim jeweiligen Alarm
  • Alle quittieren: Schaltfläche „Alle quittieren" oben rechts (nur Admin/Operator)
  • Quittierung via Push-Benachrichtigung: Direkt aus dem Benachrichtigungs-Popup (Android)
🚨

Das rote Banner am oberen Rand erscheint, solange kritische Alarme unquittiert sind. Es verschwindet erst, wenn alle kritischen Alarme bestätigt wurden.

Sensoren & Hardware

Live-Sensor-Monitoring mit automatischer Alarm-Auslösung

Das Sensor-Modul überwacht beliebige Messwerte in Echtzeit. Jeder Sensor hat definierte Min/Max-Schwellenwerte. Bei Überschreitung wird automatisch ein Alarm mit dem entsprechenden Schweregrad ausgelöst.

Sensor-Typen

🌡 Temperatur
💧 Feuchtigkeit
🔥 Rauchmelder
⚡ Strom / Spannung
🔊 Lärmpegel
💨 Luftqualität / CO₂
📊 Druck
🌊 Füllstand

Sensor-Karten

Jeder Sensor wird als Karte mit Live-Messwert, Einheit, Min/Max-Balken und Status-Badge dargestellt. Im Alarm-Zustand pulsiert die Karte rot. Das Diagramm der letzten 24 Stunden zeigt den Verlauf.

Sensor anlegen

Über + Neuer Sensor: Name, Typ, Einheit (z.B. °C, %, dB), Standort, GPS-Koordinaten und Schwellenwerte (Min/Max) festlegen. Der Simulator generiert danach automatisch realistische Messwerte.

Navigation

Turn-by-Turn mit Sprachansage

Das Navigationsmodul bietet Abbiegungsanweisungen Schritt für Schritt – vergleichbar mit Google Maps oder Apple Maps – direkt in der Plattform. Es verwendet OpenRouteService (kostenlose, quelloffene API) und GPS des Geräts.

Funktionen

  • Start per Adresseingabe oder GPS-Knopf 📍 (aktueller Standort)
  • Transportmodi: 🚗 Auto / 🚲 Fahrrad / 🚶 Zu Fuß
  • Animierte Route auf der Karte (gestrichelte Linie)
  • Große Abbiegungsanweisung oben (Pfeil + Text + Entfernung)
  • Scrollbare Schritt-für-Schritt-Liste aller Anweisungen
  • ETA und Gesamtentfernung in der Statusleiste
  • Sprachansagen via SpeechSynthesis (DE/EN/FR passend zur Spracheinstellung)
  • Automatisches Nachjustieren bei GPS-Abweichung (Neuberechnung)
  • Integration ins Flottenmodul: Fahrzeugziel direkt als Navigationsziel übernehmen

Route starten

Start eingeben

Adresse eintippen oder 📍 für GPS-Standort klicken

Ziel eingeben

Zieladresse oder Koordinaten im Format „lat, lng"

Transportmodus wählen

Auto, Fahrrad oder Zu Fuß

▶ Navigation starten

Route wird berechnet, GPS-Tracking beginnt, Sprachansagen starten

KI-Analytik

Anomalie-Erkennung und Trendanalyse

Das Analytik-Modul wertet alle Sensordaten, Alarme und Vorfälle statistisch aus und erkennt automatisch Anomalien durch Z-Score-Analyse.

🚨

🔥

Heatmap

Aktivitätsmuster der letzten 24 Stunden nach Stunde

Anomalie-Erkennung

Für jeden Sensor berechnet das System den Z-Score der letzten Messung im Vergleich zu historischen Werten. Abweichungen über 2 Sigma werden als Anomalie markiert, über 3 Sigma als kritische Anomalie – mit einem farbigen Fortschrittsbalken in der Karte.

Push-Benachrichtigungen

Alarme auch bei geschlossenem Browser – inkl. Stummodus-Bypass

Atlas AdminSysOP nutzt die Web Push API mit Service Worker, um Benachrichtigungen direkt ans Gerät zu senden – auch wenn der Browser geschlossen ist oder die App im Hintergrund läuft.

Push aktivieren

Einstellungen öffnen

⚙ unten links → Einstellungen

„🔔 Push-Benachrichtigungen aktivieren" klicken

Browser fragt nach Berechtigung – Zulassen wählen

Bestätigung

Status wechselt auf „Aktiv". Test-Benachrichtigung optional versenden.

Stummodus & DND-Bypass

🔊 Wie kritische Alarme den Stummodus umgehen:

  • Android: silent: false in der Benachrichtigung erzwingt Ton und Vibration auch bei aktiviertem „Nicht stören". Vibrationsmuster: Kritisch = 3× lang [300ms, 100ms, 300ms, 100ms, 600ms]
  • iOS (PWA): App als PWA installieren (Safari → „Zum Home-Bildschirm") für beste Ergebnisse. Ab iOS 16.4 unterstützt WebKit Web Push in installierten PWAs.
  • Desktop: Browser muss zumindest im Hintergrund laufen. Systembenachrichtigungen erscheinen unabhängig vom Browser-Fokus.

Pager Gateway

Bidirektionales POCSAG-Gateway mit universeller Push-Abdeckung

Voraussetzung: Amateurfunklizenz erforderlich für DAPNET-Sendebetrieb. Empfang (RX) ist lizenzfrei. Hardware: RTL-SDR V3/V4 USB-Dongle für RX, RPiTX (GPIO4) oder HackRF One für TX.

Architektur

Das Pager Gateway verbindet Atlas AdminSysOP mit dem DAPNET-Netzwerk (hampager.de) und sorgt dafür, dass Alarme gleichzeitig über alle Kanäle zugestellt werden:

KanalGeräteMethode
🌐 Web Push (VAPID)Browser, PWA (alle Geräte)Service Worker + Push-API
📱 ntfyAndroid & iOS (App Store)Self-hosted ntfy + APNs-Relay
🔗 AppriseTelegram, E-Mail, Discord, Signal, Slack, Matrix u.v.m.90+ Dienste via apprise-Bibliothek
📟 DAPNETEchte Pager-Hardware (BOS, Feuerwehr, Industrie)hampager.de REST-API

Tab 1 – Empfangen (POCSAG RX)

  • Receiver starten/stoppen: Startet den RTL-SDR mit multimon-ng als Hintergrundprozess. Empfängt POCSAG512/1200/2400 automatisch.
  • Live-Feed: Empfangene Nachrichten erscheinen in Echtzeit im Feed (WebSocket). Jede Nachricht zeigt Capcode, Protokoll, Frequenz und Zeitstempel.
  • Frequenz & Gain: Standard 439,9875 MHz (DAPNET Deutschland). Gain 0–50 dB einstellbar.
  • Capcode-Filter: Nur bestimmte Capcodes verarbeiten (kommagetrennt). Leer = alle empfangen.
  • Atlas-Alarme aus RX: Aktiviert → jede empfangene POCSAG-Nachricht erstellt automatisch einen Atlas-Alarm mit Severity „info".

Tab 2 – Senden (DAPNET TX)

  • Nachricht senden: Max. 80 Zeichen (POCSAG Alpha). Ziel-Rufzeichen kommagetrennt eingeben.
  • DAPNET-Konfiguration: Eigenes Rufzeichen, Passwort (von hampager.de), Sendergruppe (Standard: dl-all), Schwellenwert für automatischen Versand.
  • Auto-Dispatch: Wenn aktiviert, werden Alarme mit der konfigurierten Schwere (z.B. critical,warning) automatisch als Pager-Nachricht über DAPNET gesendet.
  • DAPNET Test: Sendet eine Test-Nachricht an die konfigurierten Rufzeichen zur Verbindungsprüfung.

Tab 3 – Push-Kanäle

  • Web Push: Status des Service Worker. „Enable" aktiviert VAPID-Push für diesen Browser.
  • ntfy-Konfiguration: URL des ntfy-Servers (z.B. http://pi-hostname:2586), Topic (Standard: atlas-alerts), optionaler Bearer-Token. iOS-Tipp: upstream-base-url: https://ntfy.sh in server.yml setzen → APNs-Relay aktiv.
  • Apprise-URLs: Eine URL pro Zeile. Beispiele:
    tgram://BOTTOKEN/CHATID
    mailto://user:pass@gmail.com
    discord://WEBHOOK_ID/WEBHOOK_TOKEN
    slack://tokenA/tokenB/tokenC/channel
  • Aktive Kanäle: Checkboxen steuern, welche Kanäle beim Alarm-Dispatch aktiv sind (webpush, ntfy, apprise, dapnet).
Raspberry Pi Setup: Führe sudo bash setup-pager.sh auf dem Pi aus. Das Script installiert RTL-SDR-Treiber, multimon-ng, apprise (pip) und ntfy (systemd-Dienst auf Port 2586) vollautomatisch.

Planer / Scheduler

Geplante Alarme und Vorfälle mit flexiblen Wiederholungsregeln

Der Planer ermöglicht die zeitgesteuerte Erstellung von Alarmen und Vorfällen. Geplante Elemente werden automatisch vom Hintergrundprozess ausgelöst und über alle aktiven Kanäle verteilt.

Elemente erstellen

Über + Neues geplantes Element öffnet sich ein Formular mit folgenden Feldern:

FeldBeschreibung
TypAlarm (alert) oder Vorfall (incident)
TitelName des Alarms / Vorfalls
BeschreibungOptionaler Detailtext
SchwereKritisch / Warnung / Info — steuert Push-Versand und Kanalauswahl
WiederholungEinmalig, Täglich, Wöchentlich, Stündlich, Alle N Minuten
Nächste AusführungDatum und Uhrzeit der ersten (oder nächsten) Ausführung
AktiviertDeaktivierte Elemente werden übersprungen

Aktionen

  • ▶ Jetzt ausführen: Löst das Element sofort aus, unabhängig vom geplanten Zeitpunkt.
  • ⏸ / ▶ Aktivieren/Deaktivieren: Schaltet das Element ohne Löschen aus oder ein.
  • ✏ Bearbeiten: Öffnet das Formular zur Anpassung aller Felder.
  • 🗑 Löschen: Löscht das Element nach Bestätigung unwiderruflich.

Automatischer Ablauf

Der Hintergrundprozess scheduled_items_runner prüft alle 30 Sekunden fällige Elemente. Bei Auslösung:

  1. Alarm oder Vorfall wird in der Datenbank erstellt
  2. WebSocket-Event wird an alle verbundenen Clients gesendet
  3. Bei Schwere „Warnung" oder „Kritisch": Web Push + alle aktiven Pager-Kanäle werden ausgelöst
  4. Nächste Ausführung wird gemäß Wiederholungsregel berechnet (einmalig → deaktiviert)

API-Übersicht

REST-Endpunkte für externe Integration

Alle Daten sind über eine dokumentierte REST-API zugänglich. Authentifizierung erfolgt per Bearer-Token im Authorization-Header.

# Login – Token holen
POST  /api/auth/login          { username, password }
GET   /api/auth/me             Aktueller Benutzer

# Kerndaten
GET   /api/assets              Alle Assets
GET   /api/incidents           Alle Vorfälle
GET   /api/alerts              Alle Alarme
GET   /api/sensors             Alle Sensoren + Messwerte

# Flotte
GET   /api/fleet/vehicles      Alle Fahrzeuge
GET   /api/fleet/trips         Alle Trips
GET   /api/fleet/stats         Flotten-KPIs
GET   /api/export/fleet        CSV-Export

# Push
GET   /api/push/vapid-public-key
POST  /api/push/subscribe
POST  /api/push/test

# WebSocket
WS    /ws/{token}              Echtzeit-Event-Bus

Die vollständige API-Dokumentation ist automatisch unter http://localhost:8080/docs (Swagger UI) verfügbar.
